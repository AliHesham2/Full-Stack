# Accessibility (a11y)

## Rule: Semantic HTML first
Native elements ship keyboard handling, focus behavior, and screen-reader semantics for free. Reach for ARIA only when no native element fits.

```tsx
// ✗ Clickable div — invisible to keyboard and assistive tech
<div onClick={save}>Save</div>

// ✓
<button onClick={save}>Save</button>
```
**Buttons for actions; `<a href>` for navigation** — never fake links with buttons or vice versa.

→ Source: [react.dev/learn/accessibility](https://react.dev/learn/accessibility)

## Forms

```tsx
<label htmlFor="email">Email</label>
<input id="email" type="email" />
```
- Every input gets a real label (`htmlFor`/`id` pair or wrapping) — placeholder text is not a label
- Group related controls with `<fieldset>` + `<legend>`
- Announce validation errors next to the field with `role="alert"` → [forms.md](./forms.md)

## Lint enforcement in CI
`eslint-plugin-react-hooks` + `eslint-plugin-jsx-a11y`:
```bash
npm install -D eslint-plugin-jsx-a11y
```
Catches missing `alt`, invalid `aria-*` props, non-interactive elements with handlers, missing focus support.

## Focus management

| Situation | Rule |
|---|---|
| Modal/dialog | Native `<dialog>.showModal()` for a modal: background inertness and modal focus. Popovers are non-modal and do not trap focus → [components-and-jsx.md](./components-and-jsx.md) |
| Route change | Move focus to the new page's main heading (frameworks handle partially; verify) |
| Async action feedback | Move focus to the status message; `role="status"` announces politely, `role="alert"` urgently |

Never remove focus outlines (`outline: none` without replacement). Use `:focus-visible` for styled rings.

## ARIA in JSX

```tsx
<button aria-expanded={open} aria-controls="menu" onClick={toggle}>Menu</button>
```
- ARIA attributes keep hyphenated HTML names in JSX: aria-label, aria-expanded, aria-controls. Use jsx-a11y linting as well as TypeScript
- `aria-label` only when visible text doesn't exist — prefer visible text
- Decorative images: `alt=""`; meaningful images describe content

## Loading regions

```tsx
<div aria-live="polite">{statusMessage}</div>
```
Live regions must exist in the DOM **before** the message arrives to be announced reliably.

→ Sources: [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/), [MDN — Accessibility](https://developer.mozilla.org/en-US/docs/Web/Accessibility)
