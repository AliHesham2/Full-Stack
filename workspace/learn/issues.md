# Template Issues

Things that are **wrong in the template itself**: a Skills file with outdated or incorrect
information, a guide that contradicts another guide or itself, a broken path or link, a check that
misses what it should catch. Reported by an actually assigned operator within its allowed project/task scope. The root entry points to Roster, not a cross-project template path.
The user reviews them and fixes the template. Newest first.

The authorized maintainer validates an issue before logging it (the same as a tester's finding): open the file, and
confirm with evidence that it is really wrong.

Each entry:

```
## YYYY-MM-DD — <the issue, in one line>
- Project where it was found:
- Template file + section: e.g. workspace/docs/syntax/Express JS/security.md § CORS
- What is wrong:
- Evidence (the official doc, the failing command, the contradicting file + section):
- Proposed fix:
- Already fixed in the project: <the exact change, so the template gets the same> / no
- Status: open / fixed (in the template)
```

---

Role assignment and task permissions govern writes here. External project access, source updates and cross-project logging require separate actual authority. This record does not approve a proposed fix or replace Planner DEC/CHG and Orchestrator task records.
