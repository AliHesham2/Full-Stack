## Deliberate project translation

- Reuse the current Roster, Planner Output, internal TODO, software TODO and Designer-owned design TODO. Do not install `_bmad/`, run `uv`/BMAD helpers, introduce memlog-derived authority, add sprint trackers, invoke named BMAD agents or create a second set of planning documents.
- Current engineering guides and owner decisions stay authoritative. A source example does not authorize a new stack, starter, dependency, schema, auth model or infrastructure. Implementer's local syntax restriction remains intact; upstream advice to browse or install is not imported.
- Outcome grouping does not prohibit necessary technical foundation tasks, override actual dependency ordering, create artificial UI scope for backend-only work or release implementation before its real design prerequisites are met.
- A named source decision record is not project approval. Proposed constraints remain proposed, deferred blocking decisions remain blockers, and no readiness verdict grants dispatch, live side effects, release or a risk waiver.
- Shared constraints are referenced once from their source; task-local summaries do not weaken them. Source absorption does not authorize ignoring material that still carries downstream decisions. Keep such material explicitly required and accessible within the brief's permissions.
- Upstream multi-agent reviewers, coaching scripts, custom setup paths and automatic next-workflow invocations are not activated. Any independent review/communication follows the actual Orchestrator assignment and host permission.
- Replanning preserves IDs and historical evidence. Do not import instructions that would delete removed-item history, renumber existing IDs, overwrite owner inputs or let Planner perform a rollback/code/test correction.

These references are evidence of source methods. Use the local integrated [procedure](../SKILL.md) and [handoff contract](../handoff-todos.md), not upstream activation instructions.
